# Bitácora - Mayo 2026

- **1 de Mayo de 2026**:
  - **Analítica Conversacional para Anuncios**: Implementación de una vista especializada para medir la efectividad de los mensajes de inicio y seguimientos automáticos de ManyChat.
    - **Base de Datos**: Se extendió el modelo `LeadAnswer` agregando las columnas `id_option` (para registrar el gancho o mensaje inicial) e `id_question` (para registrar el nivel de seguimiento al que se respondió). Migración generada y aplicada.
    - **API & Ingesta**: Actualización del endpoint del webhook (`/manychat-webhook`) para capturar y persistir estas nuevas variables, y de `/manychat-webhook/ad-details/<ad_id>` para realizar la agregación de datos (`option_breakdown` y `question_breakdown`).
    - **Interfaz (Frontend)**: Reestructuración del componente `AdDetailModal.jsx` incorporando un sistema de pestañas ("Rendimiento" y "Conversaciones"). La pestaña de "Conversaciones" presenta un diseño intuitivo con tarjetas y barras de progreso porcentuales para identificar rápidamente la opción inicial ganadora y los seguimientos más efectivos.
    - **Corrección de Métricas**: Se forzó la inicialización de "Opción 1, 2, 3" y "Seguimiento 1, 2, 3" en cero desde la agregación de la API para garantizar su visibilidad constante, además de corregir un error matemático (`NaN%`) en el frontend cuando el total de interacciones era cero.
- **4 de Mayo de 2026**:
  - **Generador de UTMs y Rastreo de Audiencia**: Implementación de una herramienta interna para la creación estandarizada de URLs de campaña para landings en Hostinger.
    - **Interfaz (Frontend)**: Creación del componente `UTMGenerator.jsx` con diseño Dark Glassmorphism. Incluye validación de URLs, formateo automático (minúsculas, guiones) y función de copiado al portapapeles con feedback visual.
    - **Integración**: Incorporación del generador en el "Panel de Control Técnico" (`OperationsSettingsPage.jsx`) bajo la sección "Marketing UTMs".
    - **Base de Datos**: Creación del modelo `UTMLog` para registrar la generación de enlaces, incluyendo usuario, URL base, URL final y parámetros UTM utilizados. Migración generada y aplicada.
    - **API (Backend)**: Implementación de endpoints `POST /api/marketing/utm-logs` para el registro automático y `GET /api/marketing/utm-logs` para consulta del historial.
    - **Refinamientos de UI/UX**:
      - Limpieza visual eliminando elementos decorativos que interferían con la lectura.
      - Implementación de **Tooltips informativos** en `utm_medium` utilizando un sistema de hover con `HelpCircle` y alta visibilidad (`z-index`).
      - Estandarización de la URL base por defecto a `https://institute.thelearnation.com/`.
      - Corrección de estilos y clases de Tailwind para asegurar la consistencia del tema Dark Glassmorphism.
      - **Integración para Administradores**: Incorporación del generador en el **Marketing Intelligence Hub** (`AdminMarketingHubPage.jsx`) mediante un sistema de pestañas.

- **5 de Mayo de 2026**:
  - **Sistema de Rastreo de Campañas Externas**: Centralización de métricas para landings alojadas en Hostinger.
    - **Base de Datos**: Creación del modelo `LandingTracking` para capturar UTMs, ruta de página y referrer. Migración generada y aplicada.
    - **Seguridad (CORS)**: Configuración de autorización para el origen `https://institute.thelearnation.com`, permitiendo peticiones POST con credenciales.
    - **Dashboard Administrativo**: Implementación de una nueva pestaña "Tráfico Landings" en el **Marketing Intelligence Hub**.
    - **API & Gestión**: 
      - Implementación de `POST /api/v1/metrics/track-visit` para la ingesta de datos de tráfico externo.
      - Implementación de `GET /api/v1/metrics/track-visits` para consulta de tráfico histórico.
      - Implementación de `DELETE /api/v1/metrics/track-visit/<id>` para la depuración de registros de prueba.
    - **Interfaz (Frontend)**: Creación del componente `LandingTrafficTable.jsx` con filtrado dinámico, estados de carga y acciones de gestión (borrado) integradas.
  - **Fix: Envío de Reporte de Setter a Discord**: Corrección de un bug que impedía que los reportes diarios de setters llegaran al canal de Discord.
    - **Causa Raíz**: Al iterar sobre `stat.answers` para construir los callouts cualitativos, la clave especial `'frequent_questions'` (almacenada como metadata en el JSON) causaba un `ValueError: invalid literal for int() with base 10` al intentar convertirla a entero. Esto propagaba la excepción hasta el bloque `try/except` que también envolvía el `db.session.commit()`, ejecutando un `rollback()` innecesario y devolviendo un error 500 al frontend.
    - **Archivos Modificados**:
      - `app/api/setter.py`: Adición de un guard `if not str(q_id).isdigit(): continue` para ignorar claves no numéricas en el diccionario de respuestas. Separación del bloque `try/except` del commit del bloque del webhook de Discord para que un fallo en el envío no comprometa el guardado en BD.
      - `app/api/public/closer.py`: Misma separación preventiva del `try/except` aplicada para garantizar consistencia y robustez.
